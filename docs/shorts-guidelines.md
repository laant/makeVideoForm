# 유튜브 쇼츠 제작 기준 (작성 가이드)

> 출처 1: [@showmiinam Threads 게시물](https://www.threads.com/@showmiinam/post/DclHaNzkp8m) — "클로드 + 유튜브 쇼츠 = 자동 수익. 카메라, 얼굴 없어도 됨. 실제로 쓰는 프롬프트 12개"
> 출처 2: @yutipman Threads 게시물 — 대본/운영 규칙 (아래 "대본 규칙" 섹션)
> 정리일: 2026-09-01

얼굴·카메라·목소리 없이 Claude만으로 쇼츠 채널을 운영하는 워크플로우.
프롬프트 12개를 파이프라인 단계별로 재배열하고, 각 단계에 깔린 **작성 기준**을 추출했다.

---

## 파이프라인 개요

```
채널 기획 → 콘텐츠 제작 → 배포 최적화 → 스케일링 → 수익화/벤치마킹
 (1)        (2~6)         (7, 12)       (8, 9)      (10, 11)
```

---

## 1단계. 채널 기획 — 주제 선정

**원칙: 주제를 잘못 고르면 90%는 망한다.**

주제 선정 기준:
- 광고 단가(RPM)가 높은 주제일 것
- 경쟁 강도를 확인할 것
- 구독자 1만 기준 실제 예상 수익을 따질 것
- 자본 없이 지금 바로 시작 가능할 것
- **수익화 속도 순**으로 우선순위를 매길 것

> 프롬프트 ①
> ```
> 나 [나이]살이고 [관심사] 관심 있어
> 광고 단가 제일 높은 쇼츠 주제 5개 뽑아줘
> 경쟁 강도, 구독자 1만일 때 실제 수익,
> 돈 없이 지금 바로 시작할 수 있는 것도 포함해서
> 수익화 빠른 순으로 정리해줘
> ```

## 2단계. 콘텐츠 제작

### 2-1. 스크립트 (기본 골격)

**원칙: 스크립트 없는 쇼츠는 죽은 영상이다.**

스크립트 작성 기준:
- 길이: **45초** 분량
- 타겟 시청자를 명시하고 작성
- **첫 3초 안에 후킹 문장**
- 사실 기반 핵심 포인트 **3개**
- **댓글을 유도하는 마무리** 멘트
- 문체: 대화하듯, 짧은 문장

> 프롬프트 ②
> ```
> [주제]에 대한 45초짜리 쇼츠 스크립트 써줘 타겟은 [시청자]
> 첫 3초 안에 후킹 문장, 사실 기반 핵심 포인트 3개,
> 댓글 유도하는 마무리 멘트
> 대화하듯 짧은 문장으로 써줘
> ```

### 2-2. 후킹 문장

**원칙: 첫 3초에 시청자를 놓치면 전부 날아간다.**

후킹 문장 기준:
- 한 문장 **10단어 이하**
- 실제 사람이 말하는 톤
- 4가지 유형을 골고루: **호기심 / 충격 / 직접 질문 / 강렬한 약속**
- 다량(20개) 생성 후 선별

> 프롬프트 ③
> ```
> [주제]에 대한 쇼츠 후킹 문장 20개 써줘
> 호기심 5개 충격 5개 직접 질문 5개 강렬한 약속 5개
> 각 문장은 10단어 이하로, 실제 사람이 말하는 것처럼 써줘
> ```

### 2-3. 제목

**원칙: 제목이 클릭을 결정한다. 제목이 전부다.**

제목 기준:
- **60자 이하**
- 3가지 유형: **숫자 포함 / 질문형 / 감정 자극형**
- 다량(15개) 생성 후, 바이럴 가능성 최상위 후보와 그 이유까지 검토

> 프롬프트 ④
> ```
> [주제]에 대한 쇼츠 제목 15개 만들어줘
> 숫자 포함 5개 질문형 5개 감정 자극형 5개
> 60자 이하로 가장 바이럴 가능성 높은 제목이 뭔지랑 이유도 알려줘
> ```

### 2-4. AI 음성용 변환 (TTS 마크업)

**원칙: 목소리도 얼굴도 필요 없다.**

TTS 스크립트 변환 규칙:
- 쉬는 구간(포즈): `[...]`
- 강조: **대문자**
- 감정: `(괄호)` 안에 표시

> 프롬프트 ⑤
> ```
> 이 스크립트를 AI 음성 생성용으로 바꿔줘
> 쉬는 구간은 [...] 로, 강조할 부분은 대문자로,
> 감정은 괄호 안에 표시해줘
> 스크립트 : [스크립트 붙여넣기]
> ```

### 2-5. 시청 지속률 최적화 (리텐션 구조)

**원칙: 끝까지 보게 만드는 영상이 알고리즘에서 살아남는다.**

리텐션 구조 기준 (초 단위 설계):
- **시작과 끝을 루프 구조**로 (끝이 처음으로 자연스럽게 이어져 반복 시청 유도)
- **15초 지점: 궁금증 유발**
- **30초 지점: 반전**

> 프롬프트 ⑥
> ```
> 이 스크립트를 쇼츠 시청 지속률 최대화 버전으로 다시 짜줘
> 시작과 끝에 루프 구조, 15초 지점에 궁금증 유발,
> 30초 지점에 반전 초 단위로 최적화된 버전으로 줘
> ```

## 3단계. 배포 최적화

### 3-1. 설명란 + 해시태그

**원칙: 설명란은 공짜 노출인데 대부분 낭비한다.**

설명란 기준:
- **첫 줄에 정확한 키워드**
- 후킹 문장 3개
- 해시태그 **15개** = 인기 5 + 중간 5 + 세부(니치) 5

> 프롬프트 ⑦
> ```
> [주제]에 대한 쇼츠 설명란 최적화 버전 써줘
> 첫 줄에 정확한 키워드, 후킹 문장 3개,
> 해시태그 15개 (인기 5개, 중간 5개, 세부 5개)
> ```

### 3-2. 업로드 스케줄

**원칙: 생각날 때마다 올리면 알고리즘이 등을 돌린다. 일관성이 핵심.**

스케줄 기준:
- 30일치 업로드 캘린더를 미리 확정
- 타겟 시청자 시간대 기준 **최적 업로드 시간**
- **적정 업로드 빈도** 유지
- **주간 포맷 믹스** (요일별 콘텐츠 유형 배분)

> 프롬프트 ⑫
> ```
> [주제] 쇼츠 채널 30일치 업로드 캘린더 만들어줘
> [시간대] 기준 최적 업로드 시간,
> 적정 업로드 빈도, 주간 포맷 믹스 포함
> ```

## 4단계. 스케일링 (대량 생산)

### 4-1. 아이디어 뱅크

**원칙: 쇼츠 1개가 아니라 100개 만드는 게 진짜 문제다.**

아이디어 생성 기준:
- 30일치 = 30개 단위로 묶어 생성
- 각 아이디어: 제목 + 한 줄 후킹 + 차별화 포인트
- 개념 중복 금지
- 유형 믹스: **정보성 / 바이럴형 / 논란형**

> 프롬프트 ⑧
> ```
> [주제]에 대한 쇼츠 아이디어 30개를 30일치로 뽑아줘
> 제목, 한 줄 후킹 문장, 차별화 포인트 포함
> 개념 겹치지 않게, 정보성·바이럴·논란형 섞어서
> ```

### 4-2. 롱폼 → 쇼츠 재활용

**원칙: 롱폼 1개 = 쇼츠 10개.**

분할 기준:
- 각 쇼츠는 **독립적으로 완결** (자체 후킹 + 완결된 시작과 끝)
- 분량: **30~60초**

> 프롬프트 ⑨
> ```
> 이 긴 스크립트에서 독립적인 쇼츠 10개 뽑아줘
> 각각 자체 후킹 문장, 완결된 시작과 끝, 30~60초 분량
> 스크립트 : [내용 붙여넣기]
> ```

## 5단계. 수익화 & 벤치마킹

### 5-1. 수익화 다각화

**원칙: 애드센스는 시작일 뿐, 끝이 아니다.**

수익화 검토 기준:
- 현재 구독자 규모 기준으로 **지금 당장 가능한** 방법 7가지
- 첫 달 현실적 수익 예상치 포함
- 실행 난이도 순 정렬
- 이론이 아닌 구체적 예시

> 프롬프트 ⑩
> ```
> 나는 [주제] 쇼츠 채널 운영 중이고 구독자는 [숫자]명이야
> 지금 당장 수익화할 수 있는 방법 7가지 알려줘
> 첫 달 현실적인 수익 + 실행 난이도 순으로
> 이론 말고 구체적인 예시로
> ```

### 5-2. 경쟁 채널 벤치마킹

**원칙: 창조하지 말고 잘 되는 걸 그대로 가져와라.**

분석 기준 (경쟁 채널 5개):
- 후킹 문장의 공통 패턴
- 제목 구조
- 가장 빠르게 성장하는 채널이 **다르게 하는 것**
- 내가 파고들 수 있는 **빈틈 3가지**

> 프롬프트 ⑪
> ```
> [주제] 관련 쇼츠 채널 5개 분석해줘 : [채널명]
> 후킹 문장의 공통 패턴, 제목 구조,
> 가장 빠르게 성장하는 채널이 다르게 하는 것,
> 내가 파고들 수 있는 빈틈 3가지
> ```

## 대본 규칙 (@yutipman) — 작성·운영 체크리스트

showmiinam 프롬프트로 초안을 뽑은 뒤, 아래 규칙으로 **검수·수정**한다.
기존 기준과 충돌하는 항목은 이 규칙이 우선한다.

### 하지 말 것 7가지 (금지 → 대신 할 것)

| # | 금지 | 대신 |
|---|---|---|
| 1 | 첫 줄에 질문 던지기 | 보여줄 장면이나 단정 문장을 바로 던져라 |
| 2 | 편집부터 시작 | 첫 컷과 첫 자막부터 정해라 |
| 3 | 내 자랑 | 보는 사람이 겪는 장면부터 꺼내라 |
| 4 | 감정 0짜리 정보 자막 | "왜 지금 봐야 하는지" 한 줄을 붙여라 |
| 5 | 자막 20자 초과 | 길면 둘로 쪼개라 |
| 6 | 업로드 후 30분 방치 | 반응 확인하고 답할 말부터 준비해라 |
| 7 | CTA 누락 | 본 사람에게 **다음 행동 하나만** 말해라 |

### 댓글이 달리게 만드는 3가지

> 댓글은 성격 좋은 사람한테 달리는 게 아니라 **답하기 쉬운 영상**에 달린다.

1. **2초 안에 답할 수 있는 양자택일**을 묻는다
   - "어떻게 생각해?" ✕ → "A야 B야?" ○
   - 생각해야 하는 질문은 시청자가 그냥 넘긴다
2. **(중요) 다 설명하기 전에 끊는다**
   - 방법을 다 풀지 말고 핵심 하나를 남겨두고 끊어라
   - 끝까지 다 알려주면 이어서 말할(댓글/다음 영상) 여지가 없다
3. **소리 없이도 이해되게** 만든다
   - 소리 끄고 보는 사람이 많다
   - 마지막 장면에도 핵심 문장을 자막으로 박아라

### 기존 기준과의 충돌 정리 (이 규칙이 우선)

- **후킹**: 기존 "직접 질문형 후킹 5개" → 첫 줄 질문 금지. 질문형 후킹은 쓰지 않거나 2초-양자택일 형태로만.
- **마무리 CTA**: 기존 "댓글 유도 멘트" → 막연한 유도("알려주세요") 대신 **양자택일 질문 1개** 또는 **다음 행동 1개**로 구체화.
- **정보 포인트 3개**: 유지하되, 마지막 하나는 **다 풀지 않고 끊는** 구조로.

## 핵심 작성 기준 요약 (자동화 시 검증 룰로 사용)

| 항목 | 기준 |
|---|---|
| 영상 길이 | 45초 (재활용 분할 시 30~60초) |
| 후킹 | 첫 3초 이내, 10단어 이하, 구어체. **질문 금지 — 장면/단정 문장으로 시작** |
| 본문 | 사실 기반 핵심 포인트 3개, 짧은 대화체 문장. 시청자가 겪는 장면 중심, 자기 자랑 금지 |
| 미완결 | 마지막 포인트는 다 풀지 않고 끊기 (댓글/후속 영상 여지) |
| 리텐션 구조 | 루프 구조(시작=끝), 15초 궁금증, 30초 반전 |
| 마무리 CTA | 2초 안에 답할 양자택일 질문("A야 B야?") 또는 다음 행동 1개. 막연한 유도 금지 |
| 자막 | **한 줄 20자 이하** (길면 분할), 정보에 "왜 지금 봐야 하는지" 감정 한 줄, 무음 시청 대비 마지막 장면에 핵심 문장 자막 |
| 제목 | 60자 이하, 숫자/질문/감정 자극 유형 |
| 설명란 | 첫 줄 키워드, 후킹 3개, 해시태그 15개(인기5·중간5·세부5) |
| TTS 마크업 | 포즈 `[...]`, 강조 대문자, 감정 (괄호) |
| 업로드 | 고정 캘린더, 최적 시간대, 일관된 빈도, 주간 포맷 믹스. **업로드 후 30분 내 반응 확인·답글** |
| 콘텐츠 믹스 | 정보성·바이럴·논란형 혼합, 개념 중복 금지 |

## 자동화 파이프라인 관점 메모

프롬프트 12개는 그대로 자동화 단계로 매핑 가능:

1. **기획 (1회성)**: 주제 선정(①) → 벤치마킹(⑪) → 30일 캘린더(⑫)
2. **일일 배치**: 아이디어 뱅크(⑧)에서 오늘 아이템 선택 → 스크립트(②) → 리텐션 최적화(⑥) → **대본 검수(yutipman 룰: 첫 줄 질문 금지·자막 20자·미완결 엔딩·양자택일 CTA)** → 후킹 선별(③) → 제목 선별(④) → TTS 변환(⑤) → 설명란(⑦)
3. **재활용 트랙**: 롱폼 스크립트 → 쇼츠 10개 분할(⑨)
4. **성장 루프 (주기적)**: 수익화 점검(⑩) → 벤치마킹 갱신(⑪)

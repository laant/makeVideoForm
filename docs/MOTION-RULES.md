# MOTION-RULES — 코드 렌더 모션 쇼츠 제작 규칙

> 상태: **v1.0 확정 (2026-10-05)** — 사용자 결정: 자막 생략 기본 · 박자 맞춤/모션 블러 기본 · treatment.md 항상. `docs/PRODUCTION.md` 에서 링크.
> 대상: opus 코드 렌더(종이공작·장부지·뷰파인더 등)와 사용자 모션그래픽(26번)처럼 **화면 전체를 코드로 그리는 9:16 쇼츠**.
> 근거: [mexicat/pdoom-video](https://github.com/mexicat/pdoom-video) (MIT, 2026-09) 의 `docs/TREATMENT.md`·`docs/ENGINE.md` 를 분석해 우리 형식(세로·나레이션 중심·40~60초)에 맞게 옮김. 우리 16~26번 제작에서 사용자가 준 교정도 함께 반영.

## 0. 한 줄 원칙

**모든 프레임은 시간 `t` 하나로 결정되고, 화면에 나오는 모든 것은 나레이션의 특정 단어에 묶인다.**

---

## 1. 영상마다 `treatment.md` 한 장 (제작 전, 대본 확인과 함께 — **항상**)

대본 확인 게이트에 아래 양식을 **항상** 같이 낸다(모든 코드 렌더 모션 쇼츠). 프로젝트 폴더(`experiments/<이름>/treatment.md`)에 둔다.

```markdown
# <번호> <제목> — treatment

## 콘셉트 (한 문단)
무엇을 말하는 영상인지 + 어떤 '그림 세계'로 말하는지.

## 연결 모티프 (1개)
처음부터 끝까지 형태를 바꾸며 이어지는 요소 하나. 예: 23번 카메라 뷰파인더, 24번 장부 줄, pdoom 의 '불꽃'.

## 팔레트
기본 2색(바탕·글자) + 신호색 1 + (선택) 예외색 1 — 예외색은 한 순간만.

## 글꼴 역할
제목/숫자(굵은 고딕) · 수치·출처·각주(모노 또는 가는 고딕) · (선택) 강조 1종.

## 장면 표
| # | 나레이션 기준 단어 | 화면 아이디어 | 숫자·사실 출처 |
|---|---|---|---|

## 수정 이력
- r1 (날짜): 사용자 피드백 → 바꾼 것
```

## 2. 연출 규칙

### 2.1 첫 컷
- 첫 화면에서 **무엇에 대한 영상인지** 바로 보인다(발표·출시 정보, 날짜, 대상). 질문만 던지는 첫 컷 금지. (22번 교정)
- 소재 블로그에 대표 이미지가 있으면 첫 컷에 먼저 보여주고 멘트에 따라 장면으로 넘어간다. (23번 교정)

### 2.2 연결 모티프와 장면 변주
- 장면마다 그림 관용구(카드·차트·서류·계기판·뷰파인더…)는 바꿔도 된다. 대신 **팔레트·글꼴·질감·여백은 영상 전체에서 하나**.
- 연결 모티프는 장면 전환 때 다음 장면의 요소로 **변신**하며 넘어가는 것이 이상적(예: 막대 → 장부 줄 → 체크 표시).

### 2.3 팔레트
- 기본 2색 + 신호색 1. 신호색은 "지금 말하는 핵심"(현재 숫자, 강조 단어)에만.
- 예외색은 영상당 1회, 한 장면 안에서만.
- 빛번짐·글로우는 신호색에만. 본문 글자는 번지지 않고 또렷하게.
- 평가 색(긍정/주의/부정)을 쓰면 화면에 "색은 해석 관점, 매수 신호 아님"을 같이 둔다. (26번)

### 2.4 글꼴
- 역할을 섞지 않는다: 큰 숫자·제목 / 수치·출처·각주 / 강조.
- 외곽선·후광(halo) 글자 금지. 대비는 바탕색과 글자색으로 낸다.
- 숫자와 단위는 붙여서 배치한다("+2.9만 개" 의 '개'가 떨어지지 않게 — 너비를 재서 배치). (26번)
- 화면 숫자는 아라비아 숫자, 나레이션은 한글 발음. (기존 규칙)

### 2.5 숫자는 화면 속 소품으로
- 핵심 숫자는 구석 고정 표시가 아니라 장면의 사물로: 카드, 계기판, 장부 칸, 막대, 저울.
- **숫자 카운트업(0→값 롤링) 금지** — 중간값이 실제 데이터처럼 보인다. 값은 완성된 상태로 등장. (26번 사용자 원본 원칙)
- 설명용 도식(업종 막대 등)은 실제 항목명·실제처럼 보이는 값을 쓰지 않고 "설명용 도식 · 실제 통계 아님"을 표기. (24번)

### 2.6 움직임
- 강한 이징(out-cubic/out-back/in-out), **멈췄다가 툭** — 둥둥 떠다니는 움직임 금지.
- 장면 안에서도 정지 화면을 3초 이상 두지 않는다(작은 반응: 링 펄스, 하이라이트, 카메라 미세 확대).
- 전환은 0.3~0.5초, 영상의 모티프에 맞는 방식 하나로 통일(장부 넘김, 셔터, 종이 붙임…).
- 사용자가 "충분히 인식"을 요청한 컷(상품, 핵심 숫자)은 등장 완료 후 **최소 2초 정지**. (18번)

## 3. 동기화 규칙 (가장 중요)

1. **단어보다 먼저 나오지 않는다.** 숫자·키워드·카드는 그 단어가 발음되는 시각(`wt(장면, 단어)`)에 등장한다. 0.1~0.3초 앞당김까지만 허용.
2. **시각을 숫자로 하드코딩하지 않는다.** 등장 시각은 `timing.json` 의 단어 시각에서 계산. 대본을 고쳐 다시 녹음해도 화면이 따라오게.
3. **장면 길이 = max(원래 디자인 길이, 나레이션 + 여유 0.8초).** 마지막 장면은 +1.5초 여운. (26번)
4. **하단 자막은 기본 생략.** 화면 문구(숫자·요약·키워드)가 나레이션 순서대로 등장해 자막 역할을 한다(26번 방식). 화면 문구만으로 나레이션 요지가 전달되지 않는 장면이 있으면 그 영상은 자막을 넣는다 — 이때 하단 고정(하단 350px 여백, y=1570 바닥선), 70px, 단어 묶음 단위.
5. **배경음 박자 맞춤(기본):** librosa 로 배경음 박을 뽑아 **장면 전환**과 큰 등장(카드·숫자 슬램)을 가장 가까운 박에 맞춘다. 단 나레이션 동기화(1번 규칙)가 박보다 우선 — 박에 맞추느라 단어보다 먼저 나오게 하지 않는다. 박이 불분명한 앰비언트 배경음이면 생략하고 그 사실을 보고.

## 4. 금지 목록

- 진부한 'AI' 그림: 보라·청록 네온, 빛나는 뇌, 매트릭스 코드 비, 렌즈플레어, 무의미한 파티클 성운, 스톡 AI 이미지.
- 실제 로고·실제 앱 화면 흉내. 서비스 이름은 글자로만. (23번)
- 확인 안 된 사실·수치, "실사용 후기" 표현. 출처는 화면 하단 또는 마지막 장면 + 설명란. (공통)
- 제품 그림은 실제 모양·착용 방식을 확인한 뒤에만. 확인 전 "똑같다/괜찮다" 단정 금지. (22번)
- 쇼핑 고지: 상품이 처음 나오는 컷부터(첫 화면이 상품이면 첫 화면), 상시 배너 금지. (16·17번)

## 5. 기술 규칙

- **결정론:** `frame_at(t)` 는 `t` 만의 함수. 난수는 시드 고정(`seed=…`), 현재 시각·실행 순서에 의존 금지. 스프라이트는 `setup()` 에서 미리 만들고 `draw()` 에서는 배치만.
- **안전 영역:** 9:16 기준 좌우 60px 이상, 상단 300px 아래부터 본문, 하단 1,560px 아래는 쇼츠 UI(제목·설명)와 겹치므로 필수 정보 금지(진행 막대·장식만). 오른쪽 950px 이후는 쇼츠 버튼 영역 — 핵심 숫자 금지.
- **오디오 레벨 목표:** 전체 평균 −18~−20 dB, 최대 −2 dB 이하. 배경음 단독 구간 −24~−28 dB, 나레이션 구간에서 사이드체인 덕킹. 무나레이션 영상도 배경음 평균 −30 dB 보다 작으면 안 된다(26번 원본 −40.5 dB 는 무음처럼 들림).
- **모션 블러(기본):** 프레임당 서브프레임 4장 평균(셔터 0.2, 프레임 시각 중심). 렌더 시간 약 4배. 시안·정지 화면 검수는 1장으로 빠르게, 최종 렌더만 4장. 서브프레임에서도 같은 결과가 나오도록 깜빡임·흔들림은 프레임 번호 기준으로 시드.
- 출력: 1080×1920, 30fps, H.264 CRF 18, AAC 192k, `+faststart`.

## 6. 검수 체크리스트 (게시 전)

- [ ] `treatment.md` 를 대본과 함께 확인받았는가
- [ ] 장면별 마지막 단어 직전 정지 화면 모아보기 시트를 **직접 열어** 확인(겹침·넘침·잘림)
- [ ] 첫 화면만 보고 주제가 보이는가
- [ ] 모든 숫자가 출처 원문과 일치(대조한 문장을 메모)
- [ ] 숫자·키워드가 해당 단어보다 먼저 나오지 않는가
- [ ] 안전 영역 침범 없음(특히 하단 1,560px 이하)
- [ ] 오디오: 전체 평균·최대, 배경음 단독 구간 레벨 측정
- [ ] 장면 전환이 배경음 박에 맞는가(또는 박 생략 사유 보고) · 최종 렌더가 모션 블러 4장인가
- [ ] 나레이션 인식 결과에서 오독 의심 단어 확인(예: "금리 인하나" → 인식 "이나나") — 의심되면 사용자에게 청취 확인 요청
- [ ] 썸네일: 첫 화면 또는 제목 전용 카드, 영상과 같은 팔레트
- [ ] `titles.txt`·설명란(요약 + 블로그 링크 + 출처 + 고지)

## 7. pdoom-video 와 다른 점 (그대로 옮기지 않은 것)

| pdoom-video | 우리 쇼츠 |
|---|---|
| 16:9, 60fps, 2분 37초 뮤직비디오 | 9:16, 30fps, 40~60초 |
| 노래 박자·가사 단어가 기준 | 나레이션 단어가 기준, 배경음 박자는 선택 |
| three.js·GLSL·레이마칭, 4K 렌더 2.5시간 | PIL + numpy → ffmpeg, 1분 영상 수 분 |
| 장면별 담당 에이전트 + 총괄(엔진·타임라인은 총괄만 수정) | 1인 렌더러 — 단, 공용 도구(`paperkit.py`·`audiokit.py`)는 영상별로 고치지 않고 영상 폴더 안에서 확장 |
| 화면 문구 = 가사(그림의 일부) | 화면 문구는 요약·숫자, 하단 자막은 나레이션 |
